# Session 07 — Formation Operations Engine

## Architectural transition

Session 06 answered: “How can PieroloOS structure and compare jurisdictions?”

Session 07 answers: “Once a working jurisdiction is explicitly selected, how does PieroloOS turn that context into an executable formation workflow?”

## Core rule

An analytical comparison does not automatically select a jurisdiction. The workflow requires an explicit `WorkingJurisdictionDecision`.

## State pipeline

COMPARISON SNAPSHOT
→ WORKING JURISDICTION DECISION
→ FORMATION PLAN
→ STAGES
→ TASKS
→ EVIDENCE / REVIEW GATES
→ COMPLETION
→ COMPLIANCE HANDOFF

## Task model

A task can contain:
- dependencies
- evidence requirements
- professional review requirement
- owner
- status
- due date
- completion data
- exception/blocking state

## Professional boundary

PieroloOS may prepare, coordinate, document and monitor. It does not independently determine legal validity, tax treatment, regulatory approval, banking approval, government acceptance, or professional suitability.
